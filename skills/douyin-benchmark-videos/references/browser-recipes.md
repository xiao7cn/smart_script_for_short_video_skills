# 抖音页面操作细则（视频搜寻）

下面的字段位置基于抖音网页版的常见布局。**页面改版后一切以实际 `browser_snapshot` 为准**——
不要把这里写的结构当成硬规则，它只是让你知道该去哪里找、以及哪些坑会绊住你。

---

## browsermcp 工具与它的限制

可用：`browser_navigate`、`browser_snapshot`、`browser_click`、`browser_hover`、`browser_type`、
`browser_select_option`、`browser_press_key`、`browser_wait`、`browser_screenshot`、
`browser_get_console_logs`、`browser_go_back`、`browser_go_forward`。

三个必须知道的限制：

1. **没有滚动工具**。搜索结果懒加载，要更多结果只能用 `browser_press_key` 发 `PageDown`
   或 `End`，发一次等 2 秒再重新 snapshot。
2. **点击需要 ref**。`browser_click` 的 `ref` 必须来自最近一次 snapshot，页面变化后旧 ref 失效。
3. **无法自行连接**。扩展必须由用户手动点 Connect。报 `No connection to browser extension`
   时转达用户，不要重试。

另外，视频详情页会自动播放。这不影响读取数据，但如果用户在意，可以提醒他先静音。

## URL 规则

| 目标 | URL |
| --- | --- |
| 综合搜索 | `https://www.douyin.com/search/<关键词>` |
| 视频搜索 | `https://www.douyin.com/search/<关键词>?type=video` |
| 视频详情 | `https://www.douyin.com/video/<aweme_id>` |
| 分享短链 | `https://v.douyin.com/<code>/` |

关键词必须 URL 编码，「AI就业」编码后是 `AI%E5%B0%B1%E4%B8%9A`。

`type=video` 失效时的兜底：导航到综合搜索页，snapshot 找到「视频」标签再 click。

从账号主页找视频时，导航到主页后作品列表本身就是视频入口，比搜索更精准——
如果用户已经有对标账号清单（`douyin-benchmark-accounts` 的产物），走这条路质量更高。

## 字段在哪里

**视频搜索结果列表**通常每条包含：封面图、标题（描述文案的前半截）、作者昵称、点赞数、时长。

**列表页基本不显示评论数。** 这是抖音的常态，别在列表页耗时间找它——评论数要进详情页。

**视频详情页**通常包含：完整描述文案、点赞数、评论数、收藏数、转发数、发布时间、
评论列表。这里是补齐数据和拿描述文案的地方。

注意区分两个数：**点赞**和**收藏**在详情页挨着，图标相似，容易看错。收藏数通常明显小于点赞数，
如果读到的「点赞」比预期小一个量级，检查是不是把收藏当成点赞了。

---

## 快照读不到数字怎么办

抖音的互动数字常渲染在图形节点里，可访问性快照拿不到。降级顺序：

1. `browser_screenshot` 截图直接看图读数。这是最有效的一招。
2. `browser_hover` 悬停有时会出精确值。
3. 读不到就留空。脚本会判为「需进详情页确认」而不是淘汰。

**不要猜数字**。留空只是需要补一轮，猜错会直接污染筛选结果。

## 翻页与去重

懒加载流程：snapshot → 记录本屏候选 → `PageDown` → `wait 2` → snapshot → 记录新增。

滚动后快照包含已看过的条目，**不用手动去重**，`filter_videos.py` 会从链接里提取视频 ID 去重，
并合并命中的关键词。短链和 `modal_id=` 形式的链接也能正确归一。

一个关键词翻 2-3 屏（约 20-30 条）足够。再往下相关度掉得很快，不如换关键词。

---

## 省时间的关键顺序

评论数必须进详情页，这是整个流程最大的时间成本。所以顺序要这样安排：

```
第一轮（便宜）：搜索列表页批量收集 → 标题/作者/链接/点赞数
      ↓ 只保留点赞已达标的
第二轮（贵）：逐条进详情页 → 补评论数 + 完整描述文案
      ↓
交给脚本筛选
```

第二轮只跑前 2N 条点赞最高的，凑够 N 条就停。要 10 条达标视频，第二轮通常跑 15-20 次导航，
每次间隔 2-3 秒，这一段大约需要一分钟以上，属于正常。

---

## 反爬与风控

- **频率**：每次导航、翻页之间 `browser_wait` 2-3 秒。详情页连续导航尤其容易触发风控，
  这一轮宁可慢一点。
- **验证码**：出现滑块时截图告知用户手动处理，不要自动尝试。
- **未登录**：结果受限、互动数据读不全。先让用户登录。
- **单次别贪多**：一次会话跑 3-5 个关键词、20 次以内的详情页导航是舒适区。

---

## 描述文案 ≠ 口播稿

从页面读到的 `title` 是视频描述，通常只是钩子句或摘要，不是完整口播内容。交付时必须标明这一点，
否则用户会误以为拿到了完整文案。

完整口播稿需要音频转写，走 `video-script-extract` skill。抖音的自动下载不稳定，
拿不到文件就得录屏，无法批量——所以只对最值得拆的 2-3 条做。
