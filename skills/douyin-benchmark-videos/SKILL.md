# 抖音对标视频搜寻与文案抽取

用用户自己的浏览器和登录态读取抖音搜索结果，筛出高互动视频，再抽文案。**不做任何签名逆向或接口伪造**——
抖音的 `a_bogus` 是绑定 JS 执行环境的动态签名，脚本直连必须复现它，那既是规避技术措施，
也会随平台更新反复失效。

以下路径均相对于本 `SKILL.md` 所在目录。

---

## 先说清楚文案能抽到什么程度

这一步的期待值必须提前对齐，否则批量做到一半会卡住。

| 来源 | 拿到什么 | 可靠性 |
| --- | --- | --- |
| 视频描述文案 | 标题和描述里的文字，通常是钩子句或摘要 | 高，页面直接可读 |
| 评论区置顶 | 作者补充的信息，有时是完整要点 | 中，不一定有 |
| 完整口播稿 | 需要音频转写 | **低，抖音自动下载不稳定** |

**完整口播稿是瓶颈**：抖音的通用下载工具支持时好时坏，拿不到文件就只能录屏，而录屏无法批量。
所以现实的做法是分层——先把 N 个链接和页面文案批量交付（这部分稳定），
再挑其中最值得拆的 2-3 条做完整口播稿转写。

不要试图对 10 条视频都做完整转写，那会变成 10 次手动录屏。

---

## 前置条件

1. **browsermcp 扩展必须已连接**。需要用户在浏览器工具栏点击扩展图标、再点 Connect。
   报 `No connection to browser extension` 时把这句话转达用户并停下，不要重试。
2. **抖音需已登录**，否则搜索结果受限、互动数据也读不全。
3. 每次导航或翻页之间用 `browser_wait` 停 2-3 秒，连续快速操作会触发验证码。
4. 完整口播稿转写需要 `video-script-extract` skill 和一个 ASR 后端。

## 工作流

| 步骤 | 动作 |
| --- | --- |
| 1 | 确认关键词、数量与阈值 |
| 2 | 逐个关键词搜索「视频」结果，读取候选 |
| 3 | 进详情页补评论数与描述文案 |
| 4 | 汇总成 JSON，交给脚本筛选 |
| 5 | 交付清单 + 页面文案 |
| 6 | 按需对少数几条做完整口播稿转写 |

### 步骤 1：确认参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 关键词 | 必填 | 可多个 |
| 数量 N | 10 | |
| 点赞下限 | 300 | |
| 评论下限 | 20 | |
| 排序 | 点赞 | 可选互动率或发布时间 |

用户只给了关键词和数量时用默认阈值，不要反问。

**建议主动提一句**：按互动率（评论÷点赞）排序往往比按点赞排序更有用。高赞可能只是踩了流量，
而互动率高说明选题有争议或强共鸣，拆解价值更大。

### 步骤 2：逐个关键词搜索

搜索视频的 URL 形如 `https://www.douyin.com/search/<关键词>?type=video`（关键词要 URL 编码）。
参数失效时导航到 `https://www.douyin.com/search/<关键词>`，再 `browser_snapshot` 找到
「视频」标签并 `browser_click`。

取数顺序：

1. `browser_snapshot` 读快照，拿标题、作者、链接、点赞数。
2. 快照里数字读不到时用 `browser_screenshot` 看图读数——点赞数常渲染在图形节点里。
3. 列表懒加载，用 `browser_press_key` 发 `PageDown` 或 `End` 往下滚，每次滚动后
   `browser_wait` 2 秒再重新 snapshot。**browsermcp 没有滚动工具，用按键代替。**

每条视频收集：`url`、`title`、`author`、`likes`、`published`、`duration`，以及 `keyword`。
读不到的留空，不要猜。

**搜索结果页通常只有点赞，没有评论数**——这是抖音的常态，别在列表页耗着找评论数。

### 步骤 3：进详情页补评论数

评论数基本只能在详情页拿到。为了不浪费时间，**只对点赞已达标的候选去补**。

逐条 `browser_navigate` 到视频链接，`browser_snapshot` 读评论数和完整描述文案，
每次之间 `browser_wait` 2-3 秒。顺手把描述文案也记进 `title` 字段，它是后面拆解的起点。

如果候选很多，只补前 2N 条点赞最高的，够凑出 N 条就停。

### 步骤 4：筛选

把数据写成 JSON 数组交给脚本，别自己换算「1.2万」这类展示值。

```bash
python3 scripts/filter_videos.py --input candidates.json --min-likes 300 --min-comments 20 --top 10
python3 scripts/filter_videos.py --input candidates.json --sort engagement   # 按互动率排序
python3 scripts/filter_videos.py --self-test                                 # 改动脚本后自测
```

零依赖。产物写到 `output/douyin-videos/`：

- `*-videos.md` / `.csv` / `.json` — 筛选结果
- `*-urls.txt` — 纯链接清单，一行一条，供逐条抽文案
- `*-captions.md` — 页面已读到的描述文案

### 步骤 5：交付清单

转达脚本输出的表格，并补上脚本给不了的判断：

- **哪 2-3 条最值得做完整拆解**，理由要具体（钩子类型、争议点、结构清晰度）。
- **互动率异常高的那条为什么高**，这通常是最有价值的发现。
- **缺口说明**。不足 N 条时说清差多少、建议加哪些关键词。

### 步骤 6：完整口播稿转写（按需）

只对用户挑定的少数几条做。把链接交给 `video-script-extract` skill：

```bash
python3 ../video-script-extract/scripts/fetch.py "<视频链接>"
```

它会先试自动下载，失败则打印录屏步骤。拿到文件后转写：

```bash
python3 ../video-script-extract/scripts/transcribe.py --input <文件>
```

转写完得到口播稿（无时间戳）和节奏分析，接着走 `video-script-extract` 的结构拆解模板，
最后把逻辑框架交给 `short-video-script` 做原创。

安装位置不同导致相对路径不通时，直接说明需要哪个 skill、让用户按名字调用即可。

```markdown
## 对标视频清单（关键词：<关键词列表>）

<脚本输出的表格>

### 最值得拆解的三条
1. <标题>——<理由：钩子类型/争议点/结构>

### 页面文案
<每条视频的描述文案，标明这不是完整口播稿>

### 缺口
<还差几条、建议补哪些关键词>
```

## 已知边界

- **必须有人工在场**：browsermcp 需手动连接，登录态和验证码需人处理，做不到无人值守。
- **完整口播稿无法批量**：见开头的说明。批量交付的是链接和页面文案，完整转写按条来。
- **数字是展示值**：抖音只给到「1.2万」这个精度，阈值在万级附近时有误差。
- **评论数要进详情页**：这是主要的时间成本所在，N 越大越明显。
- **不做接口直连**：不实现签名生成，也不建议第三方代抓服务（要交出账号 Cookie）。
  大规模高频需求应采购有资质的数据平台服务。
