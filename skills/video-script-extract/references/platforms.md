# 五平台取件指南与技术边界

`scripts/fetch.py` 会在运行时打印每个平台的操作步骤。本文件解释这些差异的来源，以及遇到特殊情况怎么办。

---

## 能力矩阵

| 平台 | 自动取件 | 受限原因 | 兜底方式 |
| --- | --- | --- | --- |
| YouTube | 字幕直取 | 字幕轨是公开数据，不受下载风控影响 | 无字幕轨时下音频跑 ASR |
| 小红书 | 有时可以 | 强制 `xsec_token`，裸 note id 只返回空壳页；高频请求触发验证码 | 图文笔记直接复制正文；视频笔记录屏 |
| 抖音 | 通常可以 | 要求带登录态的新鲜 Cookie；短链重定向会冲掉这份 Cookie | 录屏 |
| 快手 | 不稳定 | 同样要 Cookie，且 yt-dlp 的支持面更窄 | 录屏 |
| 视频号 | 不行 | 视频加密分发，取件需抓包拿到与文件配对的解密密钥 | 只能录屏 |

自动取件这一步完全委托给用户自行安装的 `yt-dlp`。本 skill 不内置任何解析器，因此不会出现"上周还能用、这周报错"的维护黑洞——拿不到就走录屏，路径始终可用。

YouTube 单独一档：它是唯一一个**不用拿到视频文件就能拿到文案**的平台，因此不走「下载 → 转写」的主干，而是走 `scripts/youtube.py`。

---

## 为什么不做逆向

**视频号**：视频以加密形式下发，解密需要从同一次接口响应里同时拿到加密直链和 `decode_key`，再用 WASM 生成的密钥流对文件头部做异或。这属于规避平台技术措施，本 skill 不实现。

**第三方在线解析站同样不建议**：那需要把带你身份信息的分享链接提交给对方服务器，隐私风险高，可用性也随时归零。

**录屏的代价其实很低**：拆解只需要声音，画质无所谓，一条 60 秒的视频录屏花不到一分钟。而且录屏对国内四个平台一视同仁，学一次就够。

---

## YouTube：唯一不用拿视频文件的平台

YouTube 把字幕当公开数据发，`yt-dlp -J` 返回的元信息里直接带各语言字幕轨的地址。
所以这里的最优路径不是「下载再转写」，而是**直接把字幕拿下来当口播稿**——
一条 30 分钟的视频 3 秒出稿，同样的内容跑 ASR 要五分钟以上，而且还会转错专有名词。

```bash
python3 scripts/youtube.py "https://www.youtube.com/watch?v=xxx"
python3 scripts/youtube.py --list-tracks "<链接>"     # 先看有哪些轨
```

### 三种字幕轨，质量差很远

| 类型 | 来源 | 能用来干什么 |
| --- | --- | --- |
| 手动字幕 | 作者自己上传 | 最好。标点、断行都是作者的意图，措辞和结构都可信 |
| 原语言自动字幕 | YouTube 的 ASR | 可用。中文轨通常一个标点都没有，靠停顿断句 |
| 机翻自动字幕 | 从原语言机器翻译 | **默认不用**。用词已被机器洗过一遍，拆「对方怎么措辞」等于拆机器 |

`youtube.py` 按这个顺序自动选，机翻轨要显式 `--allow-translated` 才会用，且用了会打警告。
判断机翻的依据是轨道地址带 `tlang=` 参数，这是 YouTube 自己的标记，不是猜的。

### 自动字幕的断句

中文自动字幕是**没有标点的滚动词流**，且每行会把上一行重复一遍（`aAppend` 事件）。
脚本的处理是：丢掉重复行，取词级时间戳，按 0.6 秒以上的停顿断句，超过 35 字兜底再切。

**切完不补标点。** ASR 没听出来的句读不该由我们臆断成句号——拆解看的是语义单元落在第几秒，
句号在哪不影响结论，而臆造的标点会被下游改写当成作者的原始语气。

英文轨还有个坑已经处理掉了：每行字幕的首词不带前导空格，跨行拼接会把 `to` 和 `love.`
粘成 `tolove.`。脚本在解析时补回边界空格，中文路径的清洗会再把这些空格删掉。

### 章节是白送的结构骨架

YouTube 的章节（chapters）会写进 `.rhythm.txt`。这是**作者自己标的分段**，
等于他把结构骨架直接交出来了，国内四个平台都没有这东西。拆长视频时先看它再看正文。

### 下载受风控，字幕不受

想拿音频跑 ASR 时（视频没有任何字幕轨）会撞上 YouTube 的下载风控，报
`HTTP Error 403`、`The page needs to be reloaded` 或 `Sign in to confirm you're not a bot`。
脚本会按 `android` → `default,-web_safari` → `tv` → `ios` 依次换 player client 重试，
这些都是 yt-dlp 支持的公开参数。全都失败时按顺序试：

1. `--browser chrome` 借用户浏览器里的登录态（同抖音那套，用的是用户自己的会话）
2. `brew upgrade yt-dlp`，风控变动通常几天内会被上游跟进
3. 还是不行就录屏，别自己想办法绕

注意**字幕路径基本不受这套风控影响**——所以「下载失败」不等于「抽不到文案」，先确认有没有字幕轨。

## 取件方式详解

### 优先级

1. **平台内保存**：作者允许下载时最省事，画质也最好。抖音、快手、小红书都在「分享」菜单里有「保存到相册」。选项灰掉说明作者关了下载权限，直接走录屏。
2. **录屏**：唯一对国内四平台都成立的方式。
3. **自动下载**：`fetch.py` 会尝试，成功算捡到便宜。

### 录屏要点

**macOS**：`Shift+Cmd+5` 选区域录制，或 QuickTime「新建屏幕录制」。默认不录系统内声音——需要装 BlackHole 之类的虚拟声卡把系统音路由进去，或者更省事的办法：**用手机播放、Mac 录不了就直接在手机上录屏**。

**iOS**：设置 → 控制中心 → 加入「屏幕录制」。下拉控制中心长按录制按钮可选是否开麦克风。录系统内声音不需要开麦克风，保持关闭反而更干净。

**Android**：通知栏「屏幕录制」，务必在弹窗里选「内部音频」或「媒体音频」，选「麦克风」会录进环境噪音。

录完从相册导出到电脑，路径喂给 `transcribe.py` 即可。ASR 只关心声音清不清楚。

### 小红书的两种笔记

**图文笔记**：正文就是完整文案，直接复制粘贴，不需要转写也不需要下载。这是国内四平台里最省事的情况，拿到就能进拆解。

**视频笔记**：链接必须是从 App 分享或搜索结果里拿到的完整 URL，形如 `https://www.xiaohongshu.com/explore/<id>?xsec_token=<token>&xsec_source=pc_share`。只有 note id 的链接拿不到内容——平台不报错也不返回数据，页面是空壳。

### 抖音的两道关：Cookie 与短链

抖音的自动取件本来是能成的，但要同时满足两个条件，缺一个都报同一句
`Fresh cookies (not necessarily logged in) are needed`，很容易误判成「平台又改了，只能录屏」。

**一、必须带登录态 Cookie。** 裸请求必定失败。`fetch.py` 用 yt-dlp 原生的
`--cookies-from-browser` 读用户本机浏览器里的会话：

```bash
yt-dlp --cookies-from-browser chrome -o "%(id)s.%(ext)s" "https://www.douyin.com/video/<id>"
```

这条路径的性质和 `douyin-benchmark-videos`、`douyin-benchmark-accounts` 用 browsermcp 操作
用户真实浏览器是一样的——用的是用户自己的登录态，不构造、不伪造任何签名，也不碰加密。
浏览器里没登录抖音时照样失败，这属于「让用户去登录」，不是「换个招绕过去」。

macOS 上首次读 Chrome Cookie 可能弹钥匙串授权，正常放行即可。多浏览器时用 `--browser`
指定到实际登录的那个，比让脚本依次探测快。

**二、短链必须先还原成规范地址。** 把 `v.douyin.com/xxx` 直接交给 yt-dlp，即使带了 Cookie 也失败：
重定向链路会把提取器需要的那份 Cookie 冲掉。正确顺序是先自己跟完重定向拿作品 ID：

```bash
curl -sIL "https://v.douyin.com/xxxxxx/" -o /dev/null -w '%{url_effective}\n'
# → https://www.douyin.com/video/7603642655055265902?previous_page=app_code_link
```

再用 `https://www.douyin.com/video/<id>` 去下载。`fetch.py` 的 `canonicalize()` 已经封装了这一步。

**快手短链** 同样会先还原再尝试借 Cookie，但 yt-dlp 对快手的支持面更窄，失败就直接录屏，不必调参。

## 已有文案的情况

用户直接粘贴了文案原文（自己扒的、图文笔记的正文、别处拿到的字幕）时，跳过取件和转写，直接进结构拆解。这种情况下缺少时间戳，钩子密度只能按字数估算——按口播约 300 字/分钟折算，每 50-75 字算一个 10-15 秒区间。

---

## 合规

- 拆解用于学习内容逻辑并产出原创，不做二次分发、不搬运、不冒用素材。
- 转写产物留在本地 `output/`，涉及他人肖像和声音的原始文件不外传。
- 不实现平台加密绕过、签名伪造、协议逆向。
