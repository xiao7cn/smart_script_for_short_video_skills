# 短视频口播文案生成

固定参数写在人设配置文件里，可变参数每次输入。工作流七步，每一步的产物都是下一步的输入。

以下所有文件路径均相对于本 `SKILL.md` 所在目录。

| 步骤 | 动作 | 产物 |
| --- | --- | --- |
| 0 | 加载人设配置（固定参数） | 人设六要素 + 25 宫格 + 输出偏好 |
| 1 | 确认可变参数，抽取选题参数卡 | N 张选题参数卡 |
| 2 | 参数卡 → 话题方向 → 选题 | N 个选题 |
| 3 | 选题 → 标题 | N 个标题 |
| 4 | 写口播正文 | ≥500 字初稿 |
| 5 | 去 AI 味重写 | 终稿 |
| 6 | 自检 | 交付 |

用户口中的"第一到第七步"（选题类型/来源/25宫格/爆款元素/标题/脚本/去AI味）对应上表的步骤 1-5，本文的编号只是执行顺序。

---

## 步骤 0：加载人设配置

按顺序查找配置文件，用找到的第一个：

1. `./persona.yaml`
2. `./.short-video-script/persona.yaml`
3. `~/.short-video-script/persona.yaml`

用户指定了 profile（如"用招聘号那份配置"）时找 `persona.<profile>.yaml`。

**找不到任何配置**：不要凭空假设人设。把 `config/persona.example.yaml` 复制到 `./persona.yaml`，告诉用户已生成模板并列出需要他填的六项，然后停下等他确认。用户说"先用示例跑一遍"时才用示例值继续。

配置里的六项固定参数决定文案的一切表达边界：

| 字段 | 作用于 |
| --- | --- |
| `persona_model` 人设模型 | 内容供给方式（干货为主还是实战 Vlog 为主） |
| `persona_position` 人设定位 | 凭什么可信——身份、价值、风格 |
| `audience` 人群画像 | 说话对象，决定人称与用词难度 |
| `audience_needs` 用户需求 | 选题内核的来源，尤其 source = 客户咨询高频提问 时 |
| `persona_style` 人设风格 | 论证方式与服务路径 |
| `value_proposition` 价值定位 | 正文能给出什么、结尾软引导给什么 |

还要读 `output` 段：`min_words`（正文字数下限）、`forbidden_words`（禁用词）、`cta_style`（软引流方式）、`cta_asset`（钩子资产）。

---

## 步骤 1：确认可变参数并抽取参数卡

可变参数共 6 个，用户指定了哪些就锁定哪些，其余交给脚本随机：

| 参数 | 取值 |
| --- | --- |
| 选题类型 | 转化类 / 破圈类 / 家长类 |
| 选题来源 | 客户咨询高频提问 / 对标爆款拆解 / 评论私信需求挖掘 / 行业热点借势融合 |
| 25 宫格配对 | 内圈 × 中圈 和/或 外圈 |
| 爆款元素句式 | 成本 / 人群 / 奇葩 / 头牌 / 怀旧 / 反差 / 最差 / 荷尔蒙 |
| 脚本类型 | 痛点科普 / Vlog叙事 / 聊天纪实 / 话题共鸣 |
| 条数 | 默认 1 |

用脚本抽取，不要自己随机——批量时脚本类型必须严格按 **痛点科普:Vlog叙事:聊天纪实:话题共鸣 = 4:1:3:2**，模型自行随机会明显偏离配比：

```bash
python3 scripts/pick.py --count 10                          # 全随机，脚本类型按 4:1:3:2
python3 scripts/pick.py --topic-type 转化类 --element 荷尔蒙   # 锁定部分参数
python3 scripts/pick.py --count 5 --seed 42                 # 复现同一批参数
python3 scripts/pick.py --list                              # 查看全部可选值及说明
```

零依赖，装了 PyYAML 会读配置里的自定义 25 宫格，没装则自动降级解析。

**批量去重**：抽到重复的参数组合，或不同参数卡指向了同一个话题，重跑脚本换掉重复项。10 条里出现 2 条讲"AI 岗位薪资"就是失败的批量。

**素材前置检查**——以下来源缺素材时先向用户索取，拿到再往下走：

- 对标爆款拆解 → 交给 `video-script-extract` skill：它负责取件、转写、输出结构拆解表与逻辑框架，拿到框架后从步骤 2 继续。该 skill 未安装时请用户直接粘贴对标文案原文。无论走哪条路，**禁止逐句改写**，只复用抽象出的结构骨架。用户明确要「按这条视频洗稿 / 改成我来讲」而不是从零选题时，改走 `video-script-rewrite`。
- 评论私信需求挖掘 → 要真实评论/私信原文。
- 行业热点借势融合 → 联网检索近期行业新闻与招聘趋势；检索不可用时请用户提供热点。

**绝不编造**用户留言、行业新闻、个人经历和具体数据。

## 步骤 2：参数卡 → 选题

两个动作，顺序不能颠倒。

**先配对出话题方向**：内圈去链接中圈或外圈，得到一个被框死在具体范围里的话题方向。

> AI就业 × 薪资 → "AI 岗位就业的薪资范围大概是多少"

**再套爆款元素句式**，话题方向才变成选题：

> "AI 岗位就业的薪资范围大概是多少" + 荷尔蒙 → "我一个朋友开法拉利撩正妹，原来他是做 AI 行业的"

元素只改变呈现角度，不改变事实。套完回头检查：正文能不能真的把这个角度讲实？讲不实就换元素，别硬套。

完整的元素句式清单、配对示例、各选题类型的写作影响，见 `references/topic-matrix.md`。

---

## 步骤 3：选题 → 标题

**选题不等于标题**：

- 选题是概念、话题领域，是贯穿全文的内容主线，看到了大概就知道他要说什么，至少知道范围和方向。
- 标题是为了吸引眼球，想怎么取都可以，甚至可以和文案没有半点关系，看到了并不确定他要说什么，但会产生好奇，从而停留下来看一看。

> 选题：能够快速减脂不反弹的 10 种方法
> 标题：一个星期我从 100 斤掉到了 90 斤，妈呀，我怎么这么牛？

唯一约束：标题可以不透露结论，但不能承诺正文给不了的东西。

**此处暂停**：把「参数卡 + 选题 + 标题」列成清单交给用户确认，再写正文。用户明确要求一次性产出时才直接往下写。

---

## 步骤 4：写口播正文

先读 `references/script-templates.md`（四类脚本的结构公式、写作要点、痛点科普完整范文）和 `references/writing-craft.md`（钩子、情绪、通病、软引流）。

硬要求：

1. 按参数卡的**结构公式**走，不要拿痛点科普的编号并列去套其他三类。
2. 正文不低于配置里的 `min_words`（默认 500 字）。
3. 只要纯口播文案，不要分镜、不要画面描述、不要运镜说明。
4. 开头 3 秒用实景开场、共情提问、反常识观点之一，且必须与正文强相关。
5. 中段每 50-75 字埋一个钩子点（口播约每分钟 300 字，即 10-15 秒一个），500 字至少 3 个。
6. 70% 篇幅只讲 1-2 个核心点，其余一笔带过——信息过载比文案长更致命。
7. 通篇"我"和"你"，带语气词，一句话只讲一件事。
8. 软引导按 `cta_style` 只放结尾，不超过全文 10%，避开 `forbidden_words`。
9. 数据给区间或给出处，主动说清代价与门槛（"出差比较多""数学基础不能太差"这类负面信息反而提升可信度）。

写作骨架标记（如「黄金 3 秒·痛点引入」）只用于自己组织结构，**交付的正文里不保留**。

---

## 步骤 5：去 AI 味

初稿完成后必须单独执行一次重写，用 `references/deai-prompt.md` 里的提示词原文，把正文复制一份加在提示词后面。

不要把写作和去 AI 味合并成一次生成——同一次生成里既写又改，模型会保留自己的表达习惯。

重写后核对：字数仍达标、事实与数据未被改动、软引导仍在结尾。跌破字数下限时补具体细节，不是补回废话。

---

## 步骤 6：自检后交付

逐条对完 `references/writing-craft.md` 末尾的自检清单再交付。最关键的一条：**朗读一遍**，拗口就改。

> 如果你的文案，你家奶奶也能听得懂，那就是一条牛逼的文案。

---

## 交付格式

单条：

```markdown
## 标题：<标题>

**选题**：<选题>
**参数**：<选题类型> | <选题来源> | <内圈 × 中圈 × 外圈> | <爆款元素> | <脚本类型>
**结构**：<结构公式>

### 正文（<字数> 字）

<纯口播文案，段落之间空行，不含任何画面与骨架标记>
```

批量：先给一张总表（序号 / 标题 / 选题 / 脚本类型 / 参数组合），再按上面的格式逐条展开正文。总表末尾附脚本类型实际配比，便于核对 4:1:3:2。

用户要求存盘时，一条一个文件存到 `output/` 下，命名 `<序号>-<脚本类型>-<标题前12字>.md`。
