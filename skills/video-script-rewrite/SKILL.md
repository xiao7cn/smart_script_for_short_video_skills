# 短视频口播文案洗稿

`video-script-extract` 负责把视频变成口播稿和拆解，`short-video-script` 负责从零选题原创。本 skill 负责**同一选题换身份、换论证、换案例**的重写。

任务不是逐句改写，也不是换同义词。三个阶段必须按顺序做完：拆解 → 方案 → 重写。分析与写作合同见 `references/rewrite-prompt.md`，按原文执行，不要简化步骤、不要跳过表格、不要合并阶段。

以下路径均相对于本 `SKILL.md` 所在目录。

---

## 对标原则：拆结构，不抄文案

找对标 ≠ 抄文案。直接抄、简单改写，永远做不过原版——别人的思路已经固化在你脑子里，二创怎么改都会觉得别扭、不满意。

正确做法：拆解同选题 / 同话题的文案结构，搭建**属于你的**逻辑架构。

1. 看对方是怎么论证观点、输出内容的
2. 挖掘有没有你想不到的角度、观点
3. 借鉴这套思考逻辑，完全原创输出属于你自己的内容

换词、换语序、换案例都算改写，不算原创。第五段三类划分（可借鉴 / 需重证 / 不沿用）没做完，不准写第九段。

## 它和另外两个 skill 怎么选

| 用户要的 | 走哪个 |
| --- | --- |
| 只有链接 / 录屏，还没有口播稿 | 先 `video-script-extract`，再回到本 skill |
| 「按这条视频改成我来讲」 | 本 skill |
| 「借鉴结构，换个选题从零写」 | `short-video-script`，选题来源选「对标爆款拆解」 |

拿不准时问一句。用户说「洗稿」「按原文重写」就留在本 skill。

## 工作流

| 步骤 | 动作 | 产物 |
| --- | --- | --- |
| 0 | 收集「我的信息」 | 身份卡 |
| 1 | 拿到完整原文 | 口播原文 |
| 2 | 按合同做三阶段写作 | 十一段产出 |
| 3 | 自检评分 < 8 的项自动改 | 终稿 |
| 4 | `check.py` 机械校验 | 通过 / 打回 |
| 5 | 去 AI 味（只改第九段） | 去味初稿 |
| 6 | 朗读测试，拗口立刻改 | 可拍口播 |

### 步骤 0：收集「我的信息」

按顺序查找人设配置，用找到的第一个：

1. `./persona.yaml`
2. `./.short-video-script/persona.yaml`
3. `~/.short-video-script/persona.yaml`

用户指定了 profile（如「用招聘号那份配置」）时找 `persona.<profile>.yaml`。

从配置映射到合同里的字段，缺的再问，**不要编人设**：

| 合同字段 | 从哪里来 | 缺了怎么办 |
| --- | --- | --- |
| 行业/赛道 | `account` / `matrix.inner` | 问 |
| 身份 | `persona_position.identity` | 问，禁止虚构年限、职级、客户量 |
| 目标受众 | `audience` | 问 |
| 拍摄场景 | 对话 | 默认「坐在办公室对镜头口播」 |
| 人物状态 | `persona_position.style` + `persona_style` | 问 |
| 内容目的 | 对话 | 问：涨粉 / 建立信任 / 引导咨询 / 引导报名 / 引发讨论 |
| 发布平台 | `platform` | 默认抖音 |
| 期望时长 | 对话 | 由字数反推（按 300 字/分钟） |
| 期望字数 | 对话；否则 `output.min_words` | 用户给区间则取上限；只给一个数则既是目标也是上限 |
| 表达风格 | `output.language_level` | 默认「大白话、口语化、节奏快、不要太像讲课」 |
| 希望补充的观点 | 对话 | 用户说「请你建议」就在第六段给建议，**先列出再写进正文** |
| 禁止出现 | `output.forbidden_words` + 对话 | 至少继承配置里的禁用词 |

没有配置也没有口述身份时：列出上表要填的项，停下等用户。用户说「先用示例跑一遍」才读 `../short-video-script/config/persona.example.yaml`。

### 步骤 1：拿到完整原文

按输入类型处理，不要猜原文：

| 用户给的 | 做法 |
| --- | --- |
| 已粘贴口播原文 | 直接用 |
| `video-script-extract` 的拆解稿 | 抽「口播原文」段；已有结构拆解可参考，但仍要按本合同重做拆解表 |
| 抖音 / 快手 / 小红书 / 视频号链接 | 交给 `video-script-extract` 取件转写，回来再洗 |
| 只给标题或摘要 | 要完整原文，摘要不够拆钩子 |

一次多条就逐条出十一段，**一条一个 md 文件**，不要合成总稿。

步骤 1 还必须记下**原视频标题**（平台上的完整标题，不要自己缩短）和**完整口播原文**。这两项要原样写进交付文档最前面，十一段之前。没有标题就写「标题未知」，不准用自己起的洗稿标题顶替。

### 步骤 2：三阶段写作

读 `references/rewrite-prompt.md`，把步骤 0–1 的身份卡和原文填进合同，再按它的顺序写。写第九段前先读 `../short-video-script/references/writing-craft.md` 的「零、全程口语化」——反面教材和正面教材就在那里，对照着写。

硬约束：

1. **先拆后写**。没有第五段的三类划分（可借鉴 / 需重证 / 不沿用），不准写第九段。
2. **第七段必须出现与原文最大的三个差异**，第九段要能对上这三条。差异必须落在论证顺序、案例和信息上，不能只换同义词。
3. 第八段给 3 个不同类型的新开头（实景 / 共情提问 / 反常识，不要三个同一种），第九段采用其中一个，不要拼三个。
4. 不虚构履历、客户数、收入、效果数据、成功案例。缺事实用一般性场景，或写「需要我补充」。
5. 原作者的个人经历、独有数据、标志性金句、连续句式，一律放进「不该沿用」，正文里换掉。
6. 第九段只要纯口播，不要分镜、画面、骨架标记。
7. **会呼吸**：通篇「我」和「你」，像跟朋友面对面聊天；自然带语气词（「对吧？」「其实啊」「你知道吗？」），不要每句都加、也不要故意堆网络热词；一句话只讲一件事，拒绝复杂长句和生僻词。
8. 第九段读起来必须像说话，不能像文章。出现「至关重要」「核心竞争力」「不可或缺」「发展趋势表明」这种书面腔，整句重写。

### 步骤 3：自检评分与自动改写

按合同第十一段打 8 项分数。**任何一项低于 8，先改第九段（必要时改第七段方案），再输出终稿**。不要带着低分交差，也不要只改分数不改文案。

改完仍要满足步骤 0 的字数上限，以及合同第三阶段的全部条款（含口语化和朗读测试）。

### 步骤 4：机械校验

把原文另存一份纯文本（或直接指向用户给的文件），跑：

```bash
python3 scripts/check.py --rewrite <洗稿.md> --original <原文.txt> \
    --min-words <下限或省略> --max-words <上限> \
    --forbidden 保证就业,包分配
```

脚本检查：原视频标题和原视频文案是否齐全、十一段是否齐全、口播字数、禁用词、与原文连续重合（≥16 字失败）、自检分是否 < 8。书面腔、缺少「我 / 你」或语气词会警告，按警告改第九段。

```bash
python3 scripts/check.py --self-test    # 脚本自测
```

未通过就按报错改第九段，再跑一遍，直到通过。连续重合失败 = 还在复述原句，要换论证路径，不是换两个同义词。

### 步骤 5：去 AI 味

这是写作之后的**独立一步**，不能和步骤 2 写在同一次生成里——同一次既写又改，模型会留下自己的表达习惯。

只重写第九段。把第九段正文原样复制一份，接在 `../short-video-script/references/deai-prompt.md` 的提示词后面，按提示词原文做一次深度重写。读不到该文件时，用下面这段：

```
请全面化身为顶级语言风格编辑、真人表达校准师与AI痕迹清除专家。
在不改变原文事实、核心观点和重要信息的前提下，对全文进行深度重写。
删除空洞开场、正确但没有信息量的废话、机械连接词、过度完整的排比、重复总结、虚假的情绪升华和教科书式表达。
重新调整句子长短、停顿节奏、观点顺序和用词密度，加入符合语境的真实细节、自然转折和明确立场，允许存在克制的不完美。
禁止堆砌网络热词、故意口语化、编造个人经历、增加原文没有的事实，以及把文章改成另一种模板化文风。
```

去味后复核：字数仍在上限内、事实没被改、禁用词没回来、软引导仍在结尾、「我 / 你」和语气词还在。

### 步骤 6：朗读测试

把去味后的第九段当成口播念一遍（至少在心里出声）。拗口、不顺耳、像在背稿，立刻改那一句，直到像平时说话。改完再跑一次 `check.py`。

第十一段「口语自然度」：没有「我 / 你」、没有语气词、读着像文章，或像 writing-craft 里那句反面教材 → 低于 8，必须改文案，不能改分数。

## 交付

文档最前面必须有原视频标题和原视频文案，再按合同十一段原样交付，顺序不要调。用户说「只要文案」也仍输出标题 + 原文 + 十一段——前八段是质量门，不是附录。

```markdown
# 洗稿：<自己的标题>

**原视频标题**：<平台上的完整标题，不要缩短>
**人设**：…　**场景**：…　**平台**：…　**目的**：…
**字数目标**：…　**时长约**：…　**风格**：…

### 原视频文案

<完整口播原文，一句一行，不要时间戳>

---

一、原文一句话总结
…
九、完整原创口播文案
…
```

用户要求存盘，或这是整次对话的最终产物时，写到仓库根目录 `output/YYYYMMDD-洗稿-<标题或钩子前12字>.md`。一次多条就各写一个文件，不要另做合集。

## 红旗：出现这些就停下来重做

| 借口 | 实际 |
| --- | --- |
| 「用户只要文案，拆解可以省」 | 先拆后写。省掉的是质量，不是时间 |
| 「换一批同义词就算原创」 | 必须换论证顺序、案例和信息，搭自己的逻辑架构 |
| 「先写完再补方案」 | 第七段是第九段的设计图，倒着做一定像复述 |
| 「原作者那个案例很强，沿用一下」 | 别人的经历和数据不沿用 |
| 「分数给低了不好看，先标 8」 | 改文案，不改分数 |
| 「像那么回事就行，不用跑脚本」 | 步骤 4 必跑 |
| 「口语化就是多加『对吧』」 | 先短句、用「我 / 你」；语气词点缀，禁止故意堆砌 |
| 「去 AI 味可以和写作一起做」 | 必须独立一步，用提示词原文重写第九段 |
| 「不用朗读，看起来通顺就行」 | 步骤 6 必做；拗口就改，不是看一眼 |
| 「对标来源写一句就够，原文在拆解稿里」 | 洗稿文档自己必须带原视频标题和完整原文 |
