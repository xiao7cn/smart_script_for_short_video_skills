# 抖音对标账号搜寻

用用户自己的浏览器和登录态读取抖音搜索结果，筛出达标账号。**不做任何签名逆向或接口伪造**——
抖音的 `a_bogus` 是绑定 JS 执行环境的动态签名，脚本直连必须复现它，那既是规避技术措施，
也会随平台更新反复失效。走真实浏览器则签名由浏览器自己生成，稳定且合规。

以下路径均相对于本 `SKILL.md` 所在目录。

---

## 前置条件

1. **browsermcp 扩展必须已连接**。它不能由 agent 自行连接，需要用户在浏览器工具栏点击 Browser MCP
   扩展图标、再点 Connect。调用浏览器工具时若报 `No connection to browser extension`，
   把这句话转达给用户并停下等待，不要重试。
2. **抖音需已登录**。未登录状态下搜索结果会被大幅限制，粉丝数等字段也常读不到。
3. 频率要收着。连续快速翻页会触发验证码，每次导航或翻页之间用 `browser_wait` 停 2-3 秒。

---

## 工作流

| 步骤 | 动作 |
| --- | --- |
| 1 | 确认关键词、数量与筛选阈值 |
| 2 | 逐个关键词搜索「用户」结果，读取候选 |
| 3 | 补齐搜索页读不到的字段（粉丝数、最近更新） |
| 4 | 汇总成 JSON，交给脚本筛选 |
| 5 | 交付清单，并说明缺口 |

### 步骤 1：确认参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 关键词 | 必填 | 可多个，逐个搜索后合并去重 |
| 数量 N | 10 | 最终输出条数 |
| 粉丝下限 | 3000 | |
| 活跃窗口 | 30 天 | 「活跃」的判定口径：最近作品在多少天内 |

用户只说了关键词和数量时，用默认阈值，不要反问。

**关键词数量的现实**：一个关键词的用户搜索结果里，达标的通常只有几个。要 10 个达标账号，
准备 3-5 个关键词。关键词不足时主动提议扩展词（同义词、人群词、痛点词），而不是硬凑。

### 步骤 2：逐个关键词搜索

搜索用户的 URL 形如 `https://www.douyin.com/search/<关键词>?type=user`（关键词要 URL 编码）。
参数若失效，就导航到 `https://www.douyin.com/search/<关键词>`，再用 `browser_snapshot`
找到「用户」标签页并 `browser_click`。

拿到列表后按这个顺序取数据：

1. `browser_snapshot` 读可访问性快照。这是首选，文本和链接都在里面。
2. 快照里数字缺失或结构混乱时，改用 `browser_screenshot` 看图读数。抖音的粉丝数常渲染在
   图形节点里，快照拿不到但截图能看清。
3. 列表是懒加载，只显示前若干条。要更多就用 `browser_press_key` 发 `PageDown` 或 `End`
   往下滚，每次滚动后 `browser_wait` 2 秒再重新 snapshot。**browsermcp 没有专门的滚动工具，
   用按键代替。**

每个账号需要收集：`nickname`、`url`（主页链接）、`followers`、`latest_post`、`works`、
`douyin_id`、`bio`，以及 `keyword`（当前搜索词）。读不到的字段留空，不要猜。

### 步骤 3：补齐缺失字段

搜索页经常不显示「最近作品时间」。缺这个字段的候选会被脚本判为「需人工确认」而不是直接淘汰。

处理原则：**只对粉丝数已达标的候选去补**，别把时间浪费在注定不合格的账号上。
逐个 `browser_navigate` 到主页，看作品列表第一条的时间，填进 `latest_post`。
每次导航之间 `browser_wait` 2-3 秒。

如果候选很多、用户也不要求精确，可以只补前 2N 个粉丝最高的，够凑出 N 个就停。

### 步骤 4：筛选

把收集到的数据写成 JSON 数组，交给脚本。脚本负责把「3.5万」「3天前」这类展示值解析成数字后比较——
不要自己在脑子里换算，容易在万/w/亿和相对时间上出错。

```bash
python3 scripts/filter_accounts.py --input candidates.json --min-followers 3000 --active-within 30 --top 10
python3 scripts/filter_accounts.py --input candidates.json --sort recent    # 按更新时间排序
python3 scripts/filter_accounts.py --self-test                              # 改动脚本后自测
```

零依赖。产物写到 `output/douyin-accounts/`，同时给出 md、csv、json 三种格式。

### 步骤 5：交付

把脚本输出的表格转达给用户，并补三件脚本给不了的判断：

- **哪几个最值得对标**，理由要具体（内容形式接近、人群重合、更新稳定）。
- **哪几个不建议对标**，比如粉丝达标但内容方向完全不同、或者靠单条爆款起量而非稳定输出。
- **缺口说明**。不足 N 个时说清差多少、建议加哪些关键词，不要假装凑够了。

---

## 交付格式

```markdown
## 对标账号清单（关键词：<关键词列表>）

<脚本输出的表格>

### 最值得对标的三个
1. <账号>——<具体理由>

### 不建议对标的
- <账号>——<原因>

### 缺口
<还差几个、建议补哪些关键词>
```

用户要求存盘时，产物已在 `output/douyin-accounts/` 下，直接告知路径。

## 已知边界

- **必须有人工在场**：browsermcp 需要手动连接，登录态和验证码也需要人处理。这个 skill 做不到无人值守。
- **数字是展示值**：抖音只给到「3.5万」这个精度，无法拿到精确粉丝数。筛选阈值在万级附近时会有误差。
- **活跃度只看最近一条**：更严谨的活跃度要看近 30 天发布条数，那需要逐个主页翻页统计，成本高很多。
  用户明确要求时再做。
- **不做接口直连**：不实现 `a_bogus`/`msToken` 之类的签名生成，也不建议使用第三方代抓服务
  （要把账号 Cookie 交给对方）。需要大规模、高频的数据时，正规做法是采购有资质的数据平台服务。
