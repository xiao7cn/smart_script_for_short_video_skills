# 抖音页面操作细则（账号搜寻）

下面的字段位置基于抖音网页版的常见布局。**页面改版后一切以实际 `browser_snapshot` 为准**——
不要把这里写的结构当成硬规则，它只是让你知道该去哪里找、以及哪些坑会绊住你。

---

## browsermcp 工具与它的限制

可用：`browser_navigate`、`browser_snapshot`、`browser_click`、`browser_hover`、`browser_type`、
`browser_select_option`、`browser_press_key`、`browser_wait`、`browser_screenshot`、
`browser_get_console_logs`、`browser_go_back`、`browser_go_forward`。

三个必须知道的限制：

1. **没有滚动工具**。抖音搜索结果是懒加载的，要更多结果只能用
   `browser_press_key` 发 `PageDown` 或 `End`。发一次等 2 秒，再重新 snapshot。
2. **点击需要 ref**。`browser_click` 的 `ref` 必须来自最近一次 `browser_snapshot`。
   页面变化后旧 ref 会失效，改动 DOM 的操作之后要重新 snapshot。
3. **无法自行连接**。扩展必须由用户手动点击 Connect。报
   `No connection to browser extension` 时转达用户，不要重试——重试不会成功。

## URL 规则

| 目标 | URL |
| --- | --- |
| 综合搜索 | `https://www.douyin.com/search/<关键词>` |
| 用户搜索 | `https://www.douyin.com/search/<关键词>?type=user` |
| 用户主页 | `https://www.douyin.com/user/<sec_uid>` |

关键词必须 URL 编码。例如「AI就业」编码后是 `AI%E5%B0%B1%E4%B8%9A`。

`type=user` 参数失效时的兜底：导航到综合搜索页，`browser_snapshot` 找到「用户」标签，
`browser_click` 切过去。这条兜底路径比记死参数可靠。

## 字段在哪里

**用户搜索结果列表**通常每条包含：昵称、抖音号、粉丝数、简介片段、几张作品缩略图。
粉丝数一般以「粉丝 3.5万」的形式出现在昵称下方。

**搜索结果列表一般不含「最近作品时间」**，这是需要进主页补的主要字段。

**用户主页**通常包含：昵称、抖音号、粉丝/关注/获赞数、简介、作品列表（含每条的发布时间或
相对时间）。作品列表第一条的时间就是「最近更新」。

判断活跃度时注意：主页作品列表默认按时间倒序，但置顶作品会排在最前面且时间可能很旧。
看到第一条时间异常旧时，检查它是不是置顶，往后看第二三条。

## 快照读不到数字怎么办

抖音有不少数字渲染在图形节点或伪元素里，可访问性快照拿不到。降级顺序：

1. `browser_screenshot` 截图，直接看图读数。短列表用这招最快。
2. `browser_hover` 悬停到数字上，有时会出现精确值的 tooltip。
3. 仍读不到就留空。脚本会把该条判为「需人工确认」而不是淘汰，交付时列出来让用户自己看一眼。

**不要猜数字**。留空比填一个错的值好得多——错的值会直接影响筛选结果，而留空只是需要人工补。

## 翻页与去重

懒加载的流程是：snapshot → 记录本屏候选 → `PageDown` → `wait 2` → snapshot → 记录新增。

滚动后的快照会包含之前已经看过的条目，**不用手动去重**，`filter_accounts.py` 会按主页链接
去重并合并命中的关键词。你只要把看到的都记下来。

翻几屏够用？一个关键词翻 2-3 屏（大约 20-30 个账号）基本能捞到该词下的主要账号，再往下
相关度会明显下降。与其在一个词上深挖，不如换一个关键词。

---

## 反爬与风控

- **频率**：每次导航、翻页、切标签之间 `browser_wait` 2-3 秒。连续快速操作最容易触发验证码。
- **验证码**：出现滑块或图形验证时，`browser_screenshot` 截图告知用户，请他手动过一下，
  然后再继续。不要尝试自动处理验证码。
- **未登录**：页面会弹登录框或结果大幅缩水。发现这种情况先告知用户去登录。
- **一次别搜太多**：单次会话搜 3-5 个关键词是舒适区。更多的话建议分几次做，中间隔开。

## 一个高效的执行节奏

对每个关键词：

```
navigate 到 ?type=user  →  wait 2  →  snapshot
  ↓ 记录本屏候选（昵称/链接/粉丝数/简介）
PageDown  →  wait 2  →  snapshot  →  记录新增
PageDown  →  wait 2  →  snapshot  →  记录新增
  ↓ 换下一个关键词
```

所有关键词跑完后，从合并的候选里挑出**粉丝数已达标**的，只对这些逐个进主页补最近更新时间。
这个顺序很重要：先用便宜的信息（粉丝数）过滤，再用贵的信息（进主页）确认，能省掉大半导航次数。
