# 闪创工厂 · 功能需求说明

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 闪创工厂（AI SHORT-VIDEO SCRIPT STUDIO） |
| 文档版本 | v1.0 |
| 文档类型 | 功能需求说明书 |
| 形态 | H5（React）优先，后续复用同一套后端接入微信小程序 |
| 依据 | `prototype/` 高保真原型 + `skills/` 下五个已验证的 AI Skills |

---

## 1. 产品定位

闪创工厂把「短视频口播文案的生产流程」产品化。

原来这套流程跑在 Cursor / Claude 这类**带 harness 的对话环境**里，由五个 Skills 承载：

| Skill | 职责 |
| --- | --- |
| `short-video-script` | 七步法从零生成选题、标题、口播正文，含去 AI 味 |
| `video-script-extract` | 抖音/快手/小红书/视频号取件 → ASR 转写 → 结构拆解 |
| `video-script-rewrite` | 基于拆解换身份、换论证、换案例重写（十一段合同） |
| `douyin-benchmark-accounts` | 对标账号筛选 |
| `douyin-benchmark-videos` | 对标视频筛选 |

产品化要解决的核心矛盾：**Skills 依赖 harness（工具调用循环 + 会话状态 + 文件读写），而 Java 后端本身没有 harness**。本项目的做法是把 harness 独立成一个可替换的 Agent 运行时（首版用 [pi](https://github.com/earendil-works/pi)），Java 只负责业务、账务与持久化。详见《系统架构设计》第 4 章。

### 1.1 目标用户

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 个人口播博主 | 自己出镜做知识/职场类账号 | 批量出选题与文案，不想每条都从零想 |
| 账号运营 | 代运营多个账号 | 一套人设配置反复复用，产出稳定 |
| MCN / 团队 | 多人协作 | 对标拆解 + 洗稿，快速跟进爆款 |

### 1.2 不做什么

- 不做视频剪辑、不做配音合成、不做发布投流。
- 不做平台加密绕过、签名伪造、协议逆向（继承 Skills 的合规底线）。
- 不代替用户编造留言、行业新闻、个人经历与具体数据。

## 3. 详细功能需求

### 3.1 账号（FR-1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1.1 | 微信一键登录 | H5 在微信内走公众号网页授权；非微信环境隐藏或降级为演示 code |
| FR-1.2 | 手机号验证码登录 | 首登即注册，无密码。验证码 6 位、有效期 5 分钟、60 秒内不可重发 |
| FR-1.3 | 账号归并 | 手机号是跨端唯一身份，先微信后短信（或反过来）认领同一账号 |
| FR-1.4 | 新用户赠额 | 注册即赠 20 条生成额度，只赠一次 |
| FR-1.5 | 登出 | 清除本地会话；服务端登录态失效 |

**非功能约束**：验证码在非生产环境直接回显在响应里（`devCode`），生产环境不回显。

### 3.2 工作台 · 六步向导（FR-2）

向导是**动态步骤流**：选到「对标爆款拆解」或「评论私信需求挖掘」时，在第 2 步后插入「对标视频」页。

| 步 | 名称 | 可选值来源 | 多选 | 可跳过 |
| --- | --- | --- | :---: | :---: |
| 1 | 选题类型 | 转化类 / 破圈类 / 家长类 | 是 | 是 |
| 2 | 选题来源 | 客户咨询高频提问 / 对标爆款拆解 / 评论私信需求挖掘 / 行业热点借势融合 | 是 | 是 |
| 2.5 | 对标视频 | 手动粘贴多条链接，或开启「自动搜索爆款视频」 | — | 是 |
| 3 | 25 宫格 | 内圈 × 中圈 × 外圈 | 三层各自多选 | 是 |
| 4 | 爆款元素 | 成本/人群/奇葩/头牌/怀旧/反差/最差/荷尔蒙 | 是 | 是 |
| 5 | 脚本类型 | 痛点科普 / Vlog 叙事 / 聊天纪实 / 话题共鸣 | 是 | 是 |
| 6 | 确认 | 选题方向补充（可选）+ 提示词预览 | — | — |

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-2.1 | 选项由服务端下发 | 25 宫格、爆款元素、脚本类型等通过 `GET /api/options` 获取，便于运营调整而不发版 |
| FR-2.2 | 未选任何项点「继续细化」 | 弹确认框询问是否跳过这一步 |
| FR-2.3 | 跳过语义 | 跳过 = 清空该步已选值，生成时由服务端从完整候选池随机补齐 |
| FR-2.4 | 脚本类型配比 | 用户不选时，批量按 **痛点科普:Vlog叙事:聊天纪实:话题共鸣 = 4:1:3:2** 用最大余数法分配，不用纯随机 |
| FR-2.5 | 提示词预览 | 实时按当前参数 + 人设拼出提示词，可手改、可重置、可复制（复制时附去 AI 味提示词） |
| FR-2.6 | 手改提示词的作用域 | 手改内容随本次生成一起提交，服务端以手改版为准 |
| FR-2.7 | 批量条数 | 1~20，预设 1/3/5/10/20 + 步进器 |
| FR-2.8 | 额度校验 | 额度不足时不发起生成；额度少于请求条数时按剩余额度生成并提示 |
| FR-2.9 | 批量去重 | 同一批内参数组合不得重复；服务端在分配参数时保证组合唯一（候选空间不足时才允许重复） |

### 3.3 生成执行（FR-3）

生成是**异步任务**：单条文案 LLM 生成耗时 30 秒以上，批量 20 条不可能同步返回。

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-3.1 | 提交即返回 | `POST /api/scripts/generate` 立即返回 `taskId`，前端跳转文案库并轮询 |
| FR-3.2 | 进度可见 | 任务含 `total / doneCount / status`，逐条完成逐条入库，前端渐进展示 |
| FR-3.3 | 七步法落地 | 服务端按 Skill 的步骤 2→3→4→5 组织提示词：配对话题方向 → 套爆款元素成选题 → 生成标题 → 写正文 → **独立一次去 AI 味重写** |
| FR-3.4 | 去 AI 味必须独立 | 写作与去味不得合并为一次 LLM 调用（同一次生成里既写又改，模型会保留自己的表达习惯） |
| FR-3.5 | 字数下限 | 正文不低于人设配置的 `min_words`（默认 500 字）；去味后跌破下限要补具体细节 |
| FR-3.6 | 禁用词 | 正文通篇避开人设里的 `banned` 词；命中则该条标记失败并重试一次 |
| FR-3.7 | 部分失败 | 单条失败不影响整批；任务终态为 `SUCCESS`（全成）/ `PARTIAL`（部分成）/ `FAILED`（全失败） |
| FR-3.8 | 额度结算 | 提交时预扣，单条失败按条退回，任务终态时对账 |
| FR-3.9 | 幂等 | 同一 `taskId` 重复轮询不产生副作用；提交携带 `requestId` 防重复下单 |

### 3.4 爆款拆解（FR-4）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-4.1 | 输入类型 | 平台链接 / 本地录屏文件 / 用户直接粘贴的文案原文 |
| FR-4.2 | 平台能力差异 | 抖音通常可自动取件（需借浏览器 Cookie + 短链还原）；快手不稳定；小红书视频需完整链接；**视频号只走录屏** |
| FR-4.3 | 取件失败 | 不反复重试、不找第三方解析站，直接返回该平台的录屏指引，等用户上传文件 |
| FR-4.4 | 转写 | ASR 后端优先级 faster-whisper → whisper.cpp → OpenAI API；产出口播稿（无时间戳）、节奏文件、句级时间戳 |
| FR-4.5 | ASR 存疑标注 | 专有名词/数字/岗位名易错，明显错字要标「此处 ASR 可能有误」，不当成事实分析 |
| FR-4.6 | 结构拆解 | 输出钩子类型、论证骨架、中段钩子位置与秒数、结尾引导方式，反推 25 宫格坐标与爆款元素 |
| FR-4.7 | 逻辑框架 | 产出「可原创复用的逻辑框架」（只留功能，不留具体内容）与「对方想到而我们没想到的角度」 |
| FR-4.8 | 交接 | 拆解完提供两个出口：洗稿（同选题换身份）/ 从零原创（只借骨架） |

### 3.5 文案重写 · 洗稿（FR-5）

严格执行 `video-script-rewrite` 的十一段合同。

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-5.1 | 三阶段顺序 | 拆解 → 方案 → 重写，不得跳过、合并或精简表格 |
| FR-5.2 | 先拆后写 | 没有第五段的三类划分（可借鉴 / 需重证 / 不沿用），不允许产出第九段 |
| FR-5.3 | 三个差异 | 第七段必须给出与原文最大的三个差异，且落在**论证顺序、案例、信息**上，不能只换同义词 |
| FR-5.4 | 三个新开头 | 第八段给 3 个不同类型（实景 / 共情提问 / 反常识），第九段只采用其中一个 |
| FR-5.5 | 原文留档 | 交付文档最前面必须有**原视频标题**与**完整口播原文**，缺一项不算交付 |
| FR-5.6 | 连续重合 | 与原文连续重合 ≥16 字视为失败，需换论证路径重写 |
| FR-5.7 | 自检评分 | 8 项各评 10 分制，任何一项 < 8 自动改文案后再输出（改文案，不改分数） |
| FR-5.8 | 去 AI 味 | 独立一步，只重写第九段 |
| FR-5.9 | 朗读测试 | 第十一段末尾必须给出「朗读测试通过 / 不通过」，不通过必须改第九段 |
| FR-5.10 | 机械校验 | 服务端复刻 `check.py` 的校验：章节齐全、字数、禁用词、连续重合、低分项、书面腔与口语标记 |

**会呼吸的硬约束**（FR-5.11）：通篇「我」和「你」；自然带语气词（「对吧？」「其实啊」「你知道吗？」）但不每句都加；一句话只讲一件事；出现「至关重要」「核心竞争力」「不可或缺」「发展趋势表明」这类书面腔整句重写。

### 3.6 文案库（FR-6）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-6.1 | 双维度筛选 | 选题类型（全部/转化类/破圈类/家长类）× 脚本类型（全部 + 四类） |
| FR-6.2 | 排序 | 按生成时间倒序 |
| FR-6.3 | 卡片信息 | 脚本类型标签、生成标记、字数、标题、选题、选题类型、爆款元素、生成时间 |
| FR-6.4 | 左滑删除 | 卡片左滑露出删除按钮，删除为软删除 |
| FR-6.5 | 详情 | 正文按段落渲染；展示选题/结构/参数/宫格/生成时间；Vlog 类展示「需替换真实素材」提示 |
| FR-6.6 | 拆解视图 | 来源为对标爆款拆解的文案，详情页提供入口查看原文 + 拆解要点 + 二创差异 |
| FR-6.7 | 复制 | 一键复制「标题 + 口播文案」 |

### 3.7 人设档案（FR-7）

对应 `persona.yaml` 的可视化。字段：人设模型、模型说明、身份定位、价值定位、表达风格、目标人群、用户需求（列表）、合规红线禁用词（标签）。

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-7.1 | 查看 / 编辑分离 | 默认只读，点「修改」进编辑态，底部「保存」才生效，「取消」丢弃草稿 |
| FR-7.2 | 恢复默认 | 一键回到系统默认人设 |
| FR-7.3 | 自动注入 | 每次生成都把人设六要素注入提示词，不需要用户重复填 |
| FR-7.4 | 禁用词继承 | 洗稿与生成都至少继承人设里的禁用词 |

### 3.8 额度与充值（FR-8）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-8.1 | 计费口径 | 每生成一条口播文案消耗 1 条额度；洗稿 1 条、拆解 1 条 |
| FR-8.2 | 套餐 | ￥19/30 条、￥59/100+15、￥149/300+60、￥399/1000+300 |
| FR-8.3 | 到账 | 支付成功后额度实时到账，写流水 |

### 3.9 AI 模型与 Harness 配置（FR-9）

这是用户明确要求的可配置可替换能力。

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-9.1 | 按场景独立配置 | **脚本生成**与**文案重写**必须是两套独立配置，可选不同 provider / 不同模型 / 不同温度 |
| FR-9.2 | 场景清单 | `SCRIPT_GENERATE`（脚本生成）、`SCRIPT_REWRITE`（文案重写）、`SCRIPT_DEAI`（去 AI 味）、`VIDEO_EXTRACT`（拆解）、`TOPIC_TITLE`（选题标题） |
| FR-9.3 | 热更新 | 改配置不重启、不发版，下一次调用生效 |
| FR-9.4 | 兜底 | 数据库无配置时回落到 `application.yml` 默认值 |
| FR-9.5 | Harness 可替换 | Harness 是一层 SPI：首版 `pi`，后续可换 `deepseek` 或自研，业务代码不改 |
| FR-9.6 | 健康检查 | 可探测当前 harness 与各 provider 的可用性 |
| FR-9.7 | 调用留痕 | 每次 LLM 调用记录场景、provider、模型、token、成本、耗时、成败 |
| FR-9.8 | 密钥不落库 | API Key 只从环境变量读取，数据库仅存**环境变量名** |

## 4. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 响应 | 非 LLM 接口 P95 < 300ms；LLM 接口一律异步，提交 < 500ms |
| 生成时延 | 单条口播（写作 + 去味两次调用）目标 < 90s；批量 20 条并发度默认 3 |
| 可用性 | LLM provider 故障时任务标 `FAILED` 并退额度，不吞额度 |
| 安全 | JWT + 服务端会话；密钥仅环境变量；用户只能访问自己的数据 |
| 合规 | 继承 Skills 底线：不绕过平台加密、不搬运、不编造事实与数据 |
| 移动适配 | H5 移动优先，最大宽度 460px 居中，与原型一致 |
| 可移植 | 业务层不依赖具体 LLM 与具体 harness，便于后续接入小程序与更换模型 |

## 5. 术语表

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 人设 | Persona | 每次生成都注入的固定设定（六要素 + 禁用词） |
| 25 宫格 | Grid | 内圈（领域）× 中圈（话题）× 外圈（人群/维度）的配对法 |
| 爆款元素 | Viral Element | 八类句式角度，只改变呈现角度不改变事实 |
| 选题 | Topic | 贯穿全文的内容主线，看到就知道大致范围 |
| 标题 | Title | 只为让人停留，可以不透露结论，但不能承诺正文给不了的东西 |
| 去 AI 味 | De-AI | 写作完成后独立执行的一次深度重写 |
| 洗稿 | Rewrite | 同选题换身份、换论证、换案例的原创重写 |
| 拆解 | Teardown | 把对标视频变成口播稿 + 结构分析 + 可复用逻辑框架 |
| Harness | Harness | 承载工具调用循环与会话状态的 Agent 运行时 |
| 额度 | Credit | 生成计费单位，1 条文案 = 1 条额度 |
